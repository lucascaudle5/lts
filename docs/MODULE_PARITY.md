# Module parity

Per module: what Lucas's earlier LTS versions meant by it, what the code does today, what is
missing, and what to build next. This is a product-intent reference. It sits under the constitution
(as amended on 2026-10-08) and the ADRs and does not override them; see the precedence list in
[`AGENTS.md`](../AGENTS.md).

- **Direction (Amendment 1):** keep the behavior Lucas actually used, add the Life Tracker OS-era
  connections, build both on the current foundation.
- **Historical column:** `H §<section>` cites a section of
  [`history/LTS_conversation_history_vs_current_repo.md`](history/LTS_conversation_history_vs_current_repo.md).
  The history is conversation-derived intent. It is not a reread of the legacy code. Where it is
  silent the cell says "not documented".
- **Current column:** checked against the code in this repo on `main` at `beb24ad`, not copied from
  the history doc. Almost every room lives in `src/app/(life)/LifeWorkspace.tsx` (3,207 lines),
  typed in `src/contracts/life.ts`, written by `src/server/mutations/workspace.ts`, and read through
  `src/server/workspace.ts`. Only Today, Tasks (`src/app/tasks/`), Settings, and capture have their
  own files. No room is a module folder yet; see [ADR 0012](adr/0012-room-modules-and-signals.md).
- **Status:** `not started`, `partial`, or `near parity`, meaning the room's own behavior; the
  cross-room signals are scored separately in the Signals column and are not built for any room.
- **Signals** use the vocabulary in [ARCHITECTURE.md](ARCHITECTURE.md#room-modules-and-signals).
  A signal asks, it never writes.

## Where the history doc and the code disagree

The history doc is intent plus a quick read of the repo. Checked against the code, these claims about
the current repo are wrong or overstated. Nothing here changes the historical intent.

1. **Fitness "protected schedule links" and Schedule "links from other records".** Not present.
   A block has no link field, and Fitness only renders a plain `Link href="/schedule"`. The same
   phrase is in `docs/LEGACY_PARITY.md`.
2. **Tasks "overdue filtering".** There is an "Overdue" text tag and Review cards. The task list is
   filtered by status tab (open, done, parked) and search, not by overdue.
3. **Habits "weekly counts" and "minimum target".** "Weekly count" is a "completed in the last 7
   days" line in the Habits room. There is no weekly or N-per-week habit rule. The single `target` is
   labeled "Minimum target", so `done` means the minimum was reached.
4. **Habits done / partial / skipped.** The room offers "Log minimum" and "Intentional skip". `partial`
   appears only by editing a log or when a `done` value is under the target.
5. **Review "recovery controls... dismiss/snooze".** The only control that changes data is "Park for
   now" on an overdue task. Dismiss and snooze live in component state and only appear as text in a
   saved review.
6. **Today and `LEGACY_PARITY.md` "meals/workouts".** Today has no meal or workout item; they appear
   only as schedule blocks.
7. **Routines "Today integration".** Today shows any logged run, including a skipped or partial one,
   as "Done. That counts."

## Implementation order

Habits, Today, Schedule, Tasks, Routines, Review, Mind, Fitness, Diet, Projects, Money, History,
Archive, Capture, Settings, Sandbox, NOVA. Optional: Boundary Map, last or never.

Dependencies and notes:

- **Habits first** because the signals contract (type, vocabulary, `get<Room>Signals` shape, the
  first `src/modules/` folder, and the import lint rule) is built with it and every later room
  reuses it.
- **Today second** because it is the first consumer of signals and already has the floor.
- **Schedule third** because it receives `needs_time` and `needs_protection`. The Schedule day rail
  (proportional 24-hour rail with a Now line, tested overlap layout, drag-to-prefill, keyboard
  navigation, previewed copy-a-day; from the Legacy B comparison in the project notes) is a Schedule
  item and belongs here, not with Habits. It is read-only rendering plus prefill, so it writes
  nothing until the user saves through the existing mutation.
- **Tasks and Routines** need Schedule's receiving side to make `needs_time` mean something.
- **Review** needs several emitters to exist before its cards beyond tasks and routines are worth
  building. **Mind** should come before Review gets capacity-aware cards.
- **Capture** gains command kinds one room at a time, so it trails the rooms it feeds.
- **Settings** carries the allowlist and module on/off. Direct execution must not widen beyond
  `Add task:` until each new command has a verified undo path (ADR 0011). That is a hard dependency
  for any NOVA "log a clearly stated entry".
- The Habits and Today guardrail tests that ban the word "streak" are changed in the same PR as the
  first streak display.

## Habits next

A 12-line spec for the first module.

1. **Purpose:** protect the floor and give Lucas a factual continuity record, where an empty day is neutral, not a failure.
2. **Owned data:** `habit` (tier, anchor, unit, minimum target, optional full target, weekday list or an N-per-week rule) and `habit_log` (one per habit per local day: completed, minimum completed, partial, skipped intentionally, missed). `no data` is the absence of a log, never stored.
3. **Core actions:** log completed, minimum, partial, or intentional skip; an explicit "mark missed" (the only action that can break a streak, offered as a recovery choice, never as a prompt); edit a log; archive and restore a habit; create and edit habits.
4. **Metrics:** current run and best run over due occurrences only; completed of due in the last N due days; weekly habits count weeks. Shown as plain facts. Local date keys only (user timezone). Partial: open question for Lucas; until decided it neither extends nor breaks a run.
5. **Signals (`getHabitSignals`):** `needs_attention` (floor habit due, no entry), `needs_protection` (anchored floor habit), `needs_recovery` (after an explicit miss, offer the minimum), `routine_candidate` (habits sharing an anchor), `review_candidate` (repeated skips or explicit misses).
6. **Today integration:** Today reads `getHabitSignals`, shows floor habits and, when the day allows, optional ones; a skipped or minimum entry counts as handled; a due day with no entry reads "no data".
7. **Boundaries:** emits signals only and never mutates another module; no red miss badge, no guilt copy, no "streak lost"; never infers completion from text; health habits (for example medication) stay out of any direct AI execution (Amendment 4).
